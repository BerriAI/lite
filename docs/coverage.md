# Feature coverage

This document distinguishes implemented behavior from planned work. A feature's existence is not evidence of complete ecosystem parity.

Latest local release verification: 1,740 unit/integration tests and all 141 browser tests passed, along with production TUI startup and interactive terminal checks. The current source runtime minimum is Node 26.4; older Node 22 results below are historical evidence.

[Litespeed 0.1.2](https://github.com/BerriAI/litespeed/releases/tag/v0.1.2) is published for Apple silicon and Intel Macs. Both [release jobs](https://github.com/BerriAI/litespeed/actions/runs/34559346612) passed fresh dependency installation, all 1,740 tests, production startup, and packaged install/update checks. The public installer was independently verified on macOS arm64 with an isolated home and no Node/Bun on PATH, including server/web startup and unconfigured gateway setup.

## Known gaps and next work

- IDE/ACP integrations and remote authenticated attach are not implemented. The TUI is implemented; native Linux/Windows terminal validation remains a follow-up. Terminal shells are process-local, macOS/Linux only, with bounded raw replay rather than a full-screen snapshot.
- Steering is delivered to the active driver; ordinary queued messages remain separate turns. Context estimates are heuristic pre-request snapshots, not tokenizer counts or a live draft meter. Automatic compaction can repeat after successful progress within a turn, including for completed work in that turn. Provider-reported usage calibrates matching request estimates. Very large indivisible prompts or tool groups still need a larger model or smaller inputs. Input-only catalog caps (LiteLLM `max_input_tokens`) budget the input estimate under a distinct "input limit" label rather than posing as total context windows, and subscription catalogs are not cached across account identities.
- Queues do not replay an already accepted turn after a process restart. Pending items require explicit Resume. Draft storage is local to each client: browser storage in the web app and a private disk cache in the TUI. It is not synchronized between clients.
- Fusion supports mutable Sidekick, Team, and Expert workers alongside bounded read-only research. Nested delegation, resumable background agents, and child MCP/questions/terminal remain unsupported. LSP diagnostics and formatters are not yet integrated. Profiles restrict built-in tools and add instructions; skills are explicit instruction text, not executable plugins. Named profiles do not enable MCP tools or delegation. Profile/model/mode configuration is not historical undo state, and imports never reactivate exported profile provenance.
- Undo/redo navigates the latest accepted turns, within a 20-turn / 32 MiB retained history budget. Recorded file-tool edits, bounded foreground command file changes, conversation, and todos can be restored; general process/MCP/terminal effects and file permissions cannot. Filesystem and SQLite changes are not jointly atomic; torn writes or conflicting external changes may need explicit recovery or manual repair.
- MCP OAuth and resources/prompts are not implemented. Tool-list notifications invalidate the catalog until explicit refresh; reconnect is always deliberate. Cancellation cannot prove a remote side effect stopped, and external effects are not undone. Remote redirects, automatic retries, and task-only MCP tools are not supported.
- Standard registered Git worktrees are supported through a narrow Git-only metadata validation path. Config includes, object alternates, and symlinked metadata are deliberately rejected; disabled filters can affect status for filtered files. This does not relax file-tool workspace boundaries.
- Server configuration uses local SQLite and environment defaults. Terminal preferences use layered JSONC. Managed policy is not implemented.
- Public sharing and hosted CI integrations are not implemented. Local plugin packages and recorded usage panels are available.

## Evidence policy

Only update a verification entry after actually running the corresponding test. Keep screenshots and private integration artifacts in ignored local storage. Never commit API credentials, subscription tokens, or real prompt data that should remain private.
